# 协作轮询：不再为权限检查读取整张导图

**基线：** `6958346`（已包含 #76 的 Loro 改名优化）。本轮只改 Worker 的协作轮询和 AI 聊天历史读取，不改变轮询间隔、增量协议或数据库结构。

## 改了什么

这两个 GET 接口原先每次都从 D1 取回 `revision` 和 `document`，但只判断行是否存在。现在它们用 `SELECT 1` 做同一个可见性判断；读取导图正文仍按需取回原字段。两种查询共用同一个 `WHERE` 和参数绑定，不缓存权限。撤销成员资格后，下次轮询仍返回 `404`，聊天历史仍返回 `200` 和空消息列表。

以 8 位读者同时轮询一张 512 KiB 导图为例，每批查询结果比原来少带 **4 MiB 正文**。这是 D1 返回给 Worker 的内容，不是浏览器下载量，也不代表少计费了多少数据库读取行。

## 本地实测

Windows、Node 26.13.0、Wrangler 4.164.0、Vitest 3.2.7。使用本地临时 D1 和真实 `handleCollab`，给每位读者直接授予只读权限。模拟没有新更新、没有在线记录的轮询；耗时从调用处理函数到读完最后一个响应。8 人一列是**整批全部完成的耗时**，不是单个请求的平均值。不含登录、浏览器渲染、网络或生产 D1 延迟。

| 导图正文 | 同时轮询的读者 | 同一 D1 实例：基线 → 优化 | 独立进程：基线 → 优化 |
| --- | ---: | ---: | ---: |
| 8 KiB | 1 | 20.06 → 19.76 ms | 24.58 → 29.54 ms |
| 8 KiB | 8 | 147.71 → 145.30 ms | 171.84 → 186.35 ms |
| 512 KiB | 1 | 25.53 → 19.29 ms | 33.17 → 25.67 ms |
| 512 KiB | 8 | 219.74 → 152.89 ms | 217.70 → 166.29 ms |

- **大图：**两种测法方向一致。同实例下，单人耗时降低 24.4%，8 人降低 30.4%；单独计时的权限查询往返从 13.01 ms 降至 6.86 ms，40 对样本均变快。
- **小图：**独立进程测得变慢，同实例则仅相差约 1–2%，两种测法方向不同。不能据此宣称小图提速，也不能把本地百分比当作线上收益。AI 聊天历史复用同一优化，但没有单独测量其延迟。

## 如何复测

在仓库根目录运行：

```sh
pnpm exec vitest bench --run apps/web/test/collab-poll.bench.ts --outputJson collab-poll.json
```

- **独立进程对照：**在基线和候选版本使用同一份基准文件及锁定依赖，依次按「旧/新、新/旧、旧/新」运行。每个场景预热 5 次、测量 21 次，不计建库时间。读取 JSON 报告的 `median`，上表取三轮中位数的中位数。
- **同实例复核：**把基线和候选版本的 `handleCollab` 载入同一进程，在同一个本地 D1、同一张图上交替按「旧→新、新→旧」调用。每个场景预热 6 对，再计时 40 对，分别取中位数。单独比较 `visibleMindmap` 与 `canViewMindmap` 时也采用同样方法。常规基准命令只测当前代码，不会自动运行此双版本对照。
- **回归验证：**6 份 TypeScript 配置、149 个 Vitest 用例、Vite 生产构建和 10 个 Chromium/WebKit 浏览器用例全部通过。新增的本地 D1 集成用例验证了工作区所有者、只读成员、成员被移除后及导图不存在时两个接口各自的响应。本机复用相同锁文件的已安装依赖；未验证全新冻结安装，也未进行生产采样或部署。
